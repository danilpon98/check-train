# trainwatch — новые вагоны и свободные кабинки на bilet.railways.kz

Самодостаточное приложение: один процесс проверяет страницу выбора вагона, показывает всё в
веб-интерфейсе и сразу сообщает о находке тремя способами: **Web Push** в браузер,
**тревога на открытой странице** (со звуком) и **Telegram** (необязательно).

## Запуск

**Windows:** дважды щёлкните `start.bat`. При первом запуске он сам создаст окружение и поставит
зависимости (нужен Python 3.11+), затем откроет интерфейс на http://localhost:8765.
Повторный запуск, когда сервис уже работает, просто откроет интерфейс.

**Вручную:**
```powershell
# 1. Создать виртуальное окружение в папке .venv: отдельная копия Python для проекта,
#    чтобы библиотеки ставились туда, а не в системный Python. Нужно один раз.
python -m venv .venv

# 2. Установить в это окружение библиотеки из requirements.txt (FastAPI, httpx, pywebpush и др.).
#    Повторять после обновления проекта, если requirements.txt изменился.
.venv\Scripts\pip install -r requirements.txt

# 3. Запустить сервис Python-ом из окружения: мониторинг + веб-интерфейс на http://localhost:8765
#    (браузер откроется сам). Без аргументов это то же самое, что «python -m trainwatch run».
#    Остановить — Ctrl+C в этом окне.
.venv\Scripts\python -m trainwatch
```

**Docker (сервер / NAS):** `docker compose up -d --build`, затем откройте http://localhost:8765.

Дальше всё делается в интерфейсе:
1. **＋ Поезд**: вставьте ссылку на страницу выбора вагона, нажмите «Проверить ссылку», затем «Добавить».
2. **Включить push** в карточке «Настройка уведомлений», затем в ⚙ отправьте «Тестовую тревогу».
3. По желанию **Telegram** в ⚙: токен от @BotFather, напишите боту `/start`, нажмите на появившийся chat_id и сохраните.

Автозапуск на Windows: `Win+R` → `shell:startup` → положите туда ярлык на `start.bat`.
Компьютер не должен засыпать, иначе проверки останавливаются.

## Развёртывание на Railway

Проект готов к Railway: образ собирается по `Dockerfile` (фронтенд собирается внутри), порт берётся
из переменной `PORT`, есть проверка здоровья `/api/health`.

1. **Загрузите код.** Либо через GitHub (приватный репозиторий → в Railway *New Project → Deploy from GitHub repo*),
   либо без GitHub через CLI: `npm i -g @railway/cli`, `railway login`, `railway init`, `railway up`
   (`.railwayignore` не даст загрузить `.env`, локальную базу и `node_modules`).
2. **Volume — обязательно.** Сервис → *Volumes* (или правый клик → *Attach Volume*), путь монтирования **`/data`**.
   Без него база, история и ключи push стираются при каждом деплое.
3. **Variables:**
   - `WEB_PASSWORD` — **обязательно**: интерфейс будет в интернете, без пароля сервис не запустится;
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — по желанию (можно ввести и в интерфейсе).
4. **Settings:**
   - *Networking → Generate Domain* — получите адрес `https://…up.railway.app`;
   - *Deploy → Healthcheck Path* = `/api/health`;
   - *Serverless / App Sleeping* — **выключено** (иначе без посетителей сервис уснёт и перестанет проверять);
   - *Replicas* = 1, регион — ближе к Казахстану (EU West или Asia Southeast).
5. **Остановите локальную копию** (`docker compose down`): два сервиса с одним Telegram-ботом мешают
   друг другу (команды бота перестают работать), а уведомления приходили бы дважды.
6. Откройте адрес, войдите паролем `WEB_PASSWORD`, добавьте поезд и включите push.

Локальные данные на Railway не переносятся — поезд добавляется заново за минуту.

**Ограничения Railway и как они учтены**

| Ограничение | Влияние | Что сделано / что делать |
|---|---|---|
| Файловая система контейнера не сохраняется между деплоями | потеря базы и ключей push | Volume на `/data` (шаг 2) |
| Инструкция `VOLUME` в Dockerfile не поддерживается | сборка падает | убрана из Dockerfile |
| HTTP-запрос живёт не дольше 15 мин | обрывается живой поток обновлений (SSE) | сервер сам переоткрывает поток раз в 10 мин, интерфейс не показывает «нет связи» при коротком переподключении |
| Исходящий IP — общий IP дата-центра (статический — только на плане Pro) | сайт railways.kz теоретически может ограничить такие запросы | проверено: страница вагонов открывается и из дата-центра в США; если начнутся блокировки — придёт предупреждение «не удаётся проверить» |
| Интерфейс доступен из интернета | любой мог бы менять настройки | обязательный `WEB_PASSWORD`, страница входа, сессия в HttpOnly-cookie, защита от перебора (5 попыток → блок на 15 мин) и от запросов с чужих сайтов |
| Платно: Hobby — $5/мес с включённым использованием на $5 | — | сервису с одним поездом этого с запасом хватает; пробный период ограничен, после него сервис остановится |

**Что становится лучше, чем локально:** сервис работает круглосуточно без вашего компьютера, а
благодаря HTTPS **push работает на любом устройстве**, включая телефон. На iPhone (iOS 16.4+) push
приходит только в приложении с экрана «Домой»: в Safari *Поделиться → На экран «Домой»*, затем
открыть оттуда и включить уведомления. На Android и компьютерах — прямо в браузере.

## Вход по паролю

Если задан `WEB_PASSWORD`, интерфейс открывается со страницы входа (без пароля, например локально, — сразу панель).

| | |
|---|---|
| «Запомнить на этом устройстве» (по умолчанию) | **30 дней с последнего визита** — пока пользуетесь, срок продлевается |
| Без галочки | до закрытия браузера, но не дольше **12 часов** |
| Завершить все сессии | ⚙ → «Вход и безопасность» → «Выйти на всех устройствах», или сменить `WEB_PASSWORD` |
| Перезапуск / деплой | сессии сохраняются (ключ подписи — `data/session_secret`) |
| Перебор пароля | 5 неудачных попыток с одного адреса → вход заблокирован на 15 минут |

Сессия — подписанная cookie (`HttpOnly`, `Secure` на HTTPS, `SameSite=Lax`): скрипты страницы её не видят,
ссылки из push и Telegram открываются без повторного входа. Push-уведомления и Telegram от входа не зависят.

| Блок | Содержимое |
|---|---|
| Шапка | связь с сервисом, интервал, статус Push и Telegram (клик открывает настройки) |
| Зелёный баннер | появляется, только когда **сейчас** есть свободная кабинка или новый вагон: что именно и кнопка «Купить» |
| Настройка уведомлений | чек-лист: поезд добавлен, push включён в этом браузере, Telegram |
| Карточка поезда | маршрут, отправление и обратный отсчёт до него, статус, «проверено N мин назад», таймер и прогресс до следующей проверки, ошибки |
| 4 показателя | свободно мест · вагонов с местами · **свободных кабинок** · **новых вагонов** (с начала отслеживания) |
| Вагоны | плитка на каждый вагон: тип, цена, число мест и **схема**: кабинки по 4 места (верхние и нижние), боковые места плацкарта. Целиком свободная кабинка подсвечена зелёным. Отмечены «НОВЫЙ» и распроданные известные вагоны |
| График | свободные места во времени (24 ч / 3 дня / неделя / всё), точки там, где была свободная кабинка, засечки неудачных проверок; таблица последних проверок |
| Лента событий | тревоги, отчёты, ошибки с фильтром; обновляется вживую. Грузится страницами по 20: на десктопе — автоматически при прокрутке ленты, на телефоне — кнопкой «Показать ещё» |
| Действия | проверить сейчас, пауза, переименовать, удалить, открыть на сайте |

## Уведомления

| Канал | Когда | Как |
|---|---|---|
| **Тревога на странице** | новый вагон / освободилась кабинка | мигающий полноэкранный оверлей, сирена (WebAudio), мигающий заголовок вкладки |
| **Web Push** | тревоги, ошибки, восстановление, «поезд ушёл»; отчёты — если включить | системное уведомление, не исчезает само, кнопки «Купить на сайте» и «Открыть trainwatch» |
| **Telegram** | всё; отчёты без звука, тревоги со звуком. Галочка «Присылать плановые отчёты» выключает отчёты — остаются тревоги, ошибки и «поезд ушёл» | очередь с повторами, переживает обрывы сети |

**Web Push на localhost.** Push работает только в «безопасном контексте». `http://localhost` им
считается, поэтому всё работает локально без HTTPS. Уведомления приходят, **даже если вкладка
закрыта**: достаточно, чтобы был запущен браузер. Доставка идёт через push-сервис производителя
браузера (Google / Mozilla / Apple), так что нужен интернет. Ключи VAPID создаются при первом запуске
в `data/vapid_private.pem`. Если открыть интерфейс по IP из локальной сети (`http://192.168…`), push
работать не будет: так устроены браузеры. Тогда нужен HTTPS или Telegram.
В Brave включите «Use Google services for push messaging».

## Правила

- **Новый вагон**: номер, которого не было ни разу с начала отслеживания.
- **Свободная кабинка**: в `div.cabin` свободны все 4 места (купе и плацкарт; боковые не считаются).
  Тревога приходит в момент освобождения; повторно — если кабинку заняли и снова освободили.
- После каждой проверки создаётся отчёт (лента, Telegram).
- Ограничение сайта: видны только вагоны, где есть места. Вагон, распроданный на момент запуска,
  при появлении в нём мест придёт как «новый вагон».

## Архитектура

```
             ┌─────────────────────── один процесс (asyncio) ───────────────────────┐
 bilet.      │  Monitor ──парсинг──► события ──► SQLite (состояние+события+outbox)  │
 railways.kz │   (задача на поезд,              │ одной транзакцией                 │
 ◄──HTTP─────┤    интервал, бэкофф)             ▼                                   │
             │                         Hub.publish ─┬─► Web Push (VAPID) ──► браузер │
             │                                      ├─► SSE ──► открытые вкладки    │
             │                                      └─► Telegram (очередь, повторы) │
             │  FastAPI: REST API + SSE + статика (без сборки и CDN)                 │
             └──────────────────────────────────────────────────────────────────────┘
```

| Модуль | Назначение |
|---|---|
| `parser.py` | разбор HTML по `data-*` атрибутам, схема мест, свободные кабинки; «пусто» отличается от «чужая страница» |
| `monitor.py` | планировщик (поезда добавляются и удаляются на лету), логика событий, тексты отчётов |
| `hub.py` | настройки и доставка событий по каналам, SSE-брокер |
| `web.py` | REST API (`/api/docs`), SSE `/api/stream`, Service Worker, статика |
| `webpush.py` | VAPID-ключи, шифрование и отправка, удаление отозванных подписок |
| `telegram.py` | очередь сообщений, команды бота, подхват токена из интерфейса |
| `state.py` | SQLite: поезда, состояние, история проверок, события, подписки, настройки |
| `static/` | **собранный** веб-интерфейс (результат `npm run build` в `frontend/`) — не править руками |

## Веб-интерфейс (`frontend/`, Vue 3)

**Стек:** Vue 3 (`<script setup>` + TypeScript) · Vite · Pinia (состояние) · VueUse (таймеры,
localStorage, размеры элементов) · Vitest + Vue Test Utils · vue-tsc. График — собственный SVG-компонент
(без тяжёлой библиотеки), роутер не нужен: это одна страница с диалогами.

Готовая сборка уже лежит в `trainwatch/static`, поэтому для обычного запуска Node.js **не нужен**.
Он нужен, только если вы меняете интерфейс.

```
frontend/src/
├─ api/            types.ts — типы ответов бэкенда · client.ts — fetch-обёртка · endpoints.ts — все запросы
├─ stores/         Pinia: app (поезда, каналы, находки) · events (лента) · settings (черновик формы)
│                  push (Service Worker, подписка) · alarm (тревога) · toast · prefs (localStorage)
├─ composables/    useLiveStream (SSE) · useNow (общие часы) · useSiren (WebAudio)
│                  useWatchHistory · useServiceWorkerMessages
├─ utils/          чистые функции: format (склонения, время) · chart (геометрия графика) · seatmap
├─ styles/         tokens.css (цвета светлой/тёмной темы) · base.css (поля форм)
└─ components/
   ├─ common/      BaseButton · BaseDialog · BasePanel · SegmentedControl · StatusChip · CheckboxField
   │               ConfirmDialog · PromptDialog · ToastHost
   ├─ layout/      AppHeader · ChannelChips · ConnectionBanner
   ├─ hero/        FindingsHero — баннер «есть свободная кабинка / новый вагон»
   ├─ setup/       SetupChecklist
   ├─ watch/       WatchList → WatchCard → WatchHeader · WatchActions · WatchTiming · WatchKpis(KpiTile)
   │               CarGrid(CarTile · SeatMap · AbsentCarTile · SeatLegend) · WatchHistory(HistoryChart · HistoryTable)
   ├─ feed/        EventFeed (десктоп — бесконечная прокрутка через useLoadMoreOnVisible, мобильный — кнопка) · EventItem
   ├─ alarm/       AlarmOverlay — полноэкранная тревога
   ├─ dialogs/     AddWatchDialog(WatchPreviewCard) · SettingsDialog
   └─ settings/    CheckSettings · PushSettings · TelegramSettings · AdvancedSettings
```

Поток данных: `GET /api/state` → store `app` → компоненты. SSE `/api/stream` присылает
`state` (перечитать состояние) и `event` (новое событие → лента, а для тревоги → `AlarmOverlay`).
Компоненты не ходят в API сами — только через stores.

**Разработка** (нужен Node.js 20.19+):
```powershell
.venv\Scripts\python -m trainwatch          # бэкенд на :8765
cd frontend
npm install                                 # один раз
npm run dev                                 # интерфейс с горячей перезагрузкой: http://localhost:5173
npm run build                               # проверка типов + сборка в trainwatch/static
npm test                                    # тесты компонентов, stores и утилит
```
В режиме `dev` запросы `/api` и `/sw.js` проксируются на бэкенд. Docker собирает интерфейс сам
(многоэтапный Dockerfile), `start.bat` — если в `trainwatch/static` нет сборки и установлен Node.js.

## Надёжность и ограничения

| Риск | Решение |
|---|---|
| Блокировка IP (WAF, ответ ~5 с) | по умолчанию раз в 15 мин + случайная добавка, 1 запрос одновременно, пауза 3 с между запросами |
| Ошибки сайта или сети | повторы через 1, 2, 4… мин; предупреждение после 3 ошибок подряд, затем сообщение о восстановлении |
| Ложное «ничего не найдено» | перепроверка через минуту, принимается после 2 подтверждений |
| Чужая страница (WAF, техработы, новая вёрстка) | считается ошибкой, а не «0 вагонов» |
| Перезапуск | всё в SQLite; ручная проверка сдвигает плановую; интервал из интерфейса применяется сразу |
| Telegram недоступен | сообщения ждут в очереди до 12 ч |
| Отозванная push-подписка | удаляется автоматически (HTTP 404/410) |
| Доступ к интерфейсу | слушает только 127.0.0.1; для сети задайте `WEB_HOST=0.0.0.0` и `WEB_PASSWORD` |
| Рост базы | отчёты и история старше 30 дней удаляются |
| Длинная история проверок | график получает её сжатой на сервере (`history.py`): серии одинаковых значений схлопываются без потерь, при нехватке места — прореживание по времени с сохранением кабинок и ошибок; 30 дней ≈ 220 точек / 24 КБ вместо 2880 / 276 КБ. Таблица «Последние проверки» грузится только при раскрытии, страницами по 20 (`/api/checks`, курсор по id), после новой проверки догружает лишь новые строки |

## Тесты
```powershell
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q          # бэкенд
cd frontend; npm test                       # интерфейс
```
Бэкенд: разбор реальных страниц сайта, логика событий, каналы доставки, REST API, отдача собранного
интерфейса, реальное шифрование Web Push с проверкой VAPID-подписи, перепланирование проверок.
Интерфейс: склонения и форматирование времени, геометрия графика, схема мест, компоненты
(SeatMap, CarTile, WatchKpis, FindingsHero), stores (лента, настройки, тревога).
